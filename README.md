# 盯防小助手 otaMonitor

单机自部署的微博数据采集与留档工具。支持任务制采集、增量更新、媒体留档、数据可视化与备份恢复。

## 功能

- 任务制采集：按目标用户、时间范围与采集身份建任务，支持断点续爬、停止保留数据、失败重试。
- 同目标再次建任务自动并入原任务，日期范围取并集。
- 采集串行与排队：同一账号始终串行，不同账号可配置并行数。
- 帖子与评论增量更新：内容变化保留旧版本，删除或隐藏的内容保留并标注。
- 版本记录：点击「编辑过」查看当前版本与历史版本，支持上一条 / 下一条翻页。
- 媒体留档：图片、视频、音频可保存到本地；按清晰度档位选择原图或高画质视频。
- 磁盘水位保护：剩余空间低于阈值时停止下载新媒体，文字与评论采集继续。
- 定时任务：每日指定时间自动增量采集，可选采集窗口。
- 数据看板：总量统计、每日增量曲线、磁盘占用趋势。
- 全文搜索：SQLite FTS5 索引，短查询自动降级 LIKE。
- Excel 导出与图表：多 Sheet 导出、按天×目标透视矩阵、评论趋势图。
- 邮件通知与 AI 周报：使用任意 SMTP 服务与 OpenAI 兼容接口，凭据加密落盘。
- 多用户：注册账号数据隔离；游客数据 14 天后过期，可合并到账号。
- 备份与恢复：个人备份与管理员整库备份，单包上限 1 GB。
- 请求加密混淆与重放防护；登录失败锁定与 IP 限流；审计日志落盘。

## 部署

### 方式一：Windows 可执行文件

1. 解压发布包，进入解压目录中的 `monitor/Windows一键版/` 文件夹。
2. 双击 `一键启动.exe`；浏览器会在数秒后自动打开。
3. 若未自动打开，手动访问 `http://127.0.0.1:8787`。

该可执行文件为单文件，无需 Python 或其他运行环境。数据保存在可执行文件同级的 `data/` 目录。关闭控制台窗口即停止服务。端口可通过环境变量 `PORT` 修改。

### 方式二：Windows 源码运行

1. 安装 Python 3.10 及以上版本，安装时勾选“Add Python to PATH”。
2. 双击项目根目录的 `start.bat`。
3. 浏览器访问 `http://127.0.0.1:8787`。

脚本自动使用 `backend/vendor/` 中的离线依赖；依赖不完整时尝试 `pip install -r requirements.txt`。

### 方式三：Linux / macOS 源码运行

```bash
chmod +x start.sh && ./start.sh
# 修改端口：PORT=9000 ./start.sh
```

数据保存在 `backend/data/`。

### 方式四：Docker Compose

```bash
docker compose up -d
```

默认挂载 `./backend:/app/backend`，代码与数据均在宿主机 `backend/` 目录。更新代码后执行 `docker compose restart` 即可生效；仅当 `requirements.txt` 变化时需要：

```bash
docker compose up -d --build --force-recreate
```


## 配置

以下环境变量均为可选项。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8787` | 服务端口 |
| `WB_DATA_DIR` | `backend/data` | 数据目录，含数据库、密钥、媒体、上传分片与审计日志 |
| `WB_DB_KEY` | 未设置时使用 `data/.key` | 落盘加密密钥；变更后原有密文无法解密 |
| `WB_REQUIRE_ENC` | `1` | 设为 `0` 关闭请求加密校验，仅用于调试 |
| `WB_MIN_ENC_VER` | `2` | 传输封装最低版本，默认 2（带完整性校验） |
| `WB_RESTORE_MAX_GB` | 同备份上限 | 恢复解压后的最大体积（GB） |
| `WB_ALLOW_REGISTER` | `1` | 设为 `0` 关闭注册；公网部署前请先关闭注册并创建管理员账号 |
| `WB_MAX_TASKS` | `1` | 并行任务数上限；同一账号始终串行 |
| `WB_MEDIA_MIN_FREE_GB` | `100` | 媒体留档的磁盘剩余水位（GB），设为 `0` 关闭 |
| `WB_MEDIA_VIDEO_MAX_MB` | `512` | 单个视频文件大小上限（MB） |
| `WB_TZ_OFFSET` | `8` | 程序时区偏移（小时，范围 -14~14），与系统时区无关；影响日期显示与定时调度，微博数据的日期归属始终按平台所在时区（UTC+8）计算 |
| `TZ` | `CST-8` | 容器系统时区，使用 POSIX 格式 |

## 备份与恢复

页面内的导出与导入仅支持 1 GB 以内的数据量。

- 超出 1 GB 时，导出与导入接口返回错误提示：请通过备份 `data` 文件夹进行迁移备份和还原。
- 个人备份包含任务、帖子、评论、版本记录与可选媒体；整库备份包含数据库、密钥与媒体，仅管理员可用。
- 恢复前自动留档当前数据，保留最近两份。
- 大数据量迁移请在停止服务后直接复制整个 `data` 目录。

`.key` 文件必须与数据库一同保存，否则 Cookie、SMTP 授权码与 AI 密钥无法解密。

## 安全说明

- 除会话引导接口外，API 请求体与 JSON 响应均使用加密封装，并校验时间戳与 nonce，拒绝重放。
- 微博 Cookie 与会话密钥以应用层加密方式入库。
- 媒体文件使用随机文件名，物理路径不对外暴露，访问需通过鉴权路由。
- 出站请求地址经过校验，禁止访问本机与内网地址，媒体下载逐跳校验重定向。
- 公网部署应配置 HTTPS 与反向代理；应用内封装不替代传输层身份认证。
- 公网部署前应设置 `WB_ALLOW_REGISTER=0`，并通过 `manage.py set-admin` 显式指定管理员，避免首访用户获得管理权限。
- 整库备份包含全部账号的 Cookie 密文与解密密钥，备份文件应加密存储并限制访问。

## 目录结构

```
monitor/
├── start.bat              Windows 源码启动
├── start.sh               Linux / macOS 源码启动
├── 更新.bat / 更新.sh       Docker 部署更新
├── 升级.sh                 源码部署升级
├── Dockerfile
├── docker-compose.yml
├── backend/
│   ├── app.py              HTTP 接口与后台作业
│   ├── db.py               数据存取
│   ├── scraper.py          采集器
│   ├── media.py            媒体留档
│   ├── exporter.py         数据导出
│   ├── vendor/             离线依赖
│   ├── static/             前端构建产物
│   ├── VERSION             版本号
│   └── data/               数据库与媒体（运行后生成）
└── web/                    前端源码
```

## 源码构建

前端源码位于 `web/`，构建产物输出到 `backend/static/`：

```bash
cd web
npm ci
npm run build
```
